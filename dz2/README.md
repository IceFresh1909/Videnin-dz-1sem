# ДЗ2 — «ФизКат»

Консольная программа учёта парка ФизКат. C++17, стандартная библиотека.
Все команды вводятся по одной в строке, `id` и `name` — без пробелов.

## Сборка и запуск

Из папки `dz2`:

```bash
clang++ -std=c++17 -Wall -Wextra -Wpedantic main.cpp -o fizkat
./fizkat
```

Пример можно проверить командой:

```bash
./fizkat < tests/example.in
```

## Команды

| Команда | Действие |
| --- | --- |
| `add scooter id name energy score` | Электросамокат |
| `add bike id name score` | Обычный велосипед |
| `add ebike id name energy score` | Электровелосипед |
| `add helmet id name` | Шлем |
| `add dock id name energy` | Док-станция |
| `add cargo id name score` | Грузовой велосипед (мой тип) |
| `list` | Все объекты по возрастанию id |
| `energy` | Суммарное потребление с одним знаком после точки |
| `novice` | Транспорт, подходящий новичкам |
| `set_novice score` | Изменить порог простоты (1–10) |
| `count_novice` | Количество подходящих новичкам единиц (моя команда) |
| `report` | Число объектов и суммарная энергия |
| `focus id` | Выставить объект на витрину |
| `show_focus` | Показать витрину или `removed` |
| `remove id` | Удалить объект из парка |
| `quit` | Выход |

Ввод транспорта с `broken` в имени (без учёта регистра) вызывает ошибку техосмотра.
Ошибки печатаются как `error: ...`, после ошибки программа продолжает читать команды.

## Иерархия классов

```text
InventoryItem (абстрактный)
├── Transport
│   ├── ElectricScooter ---- EnergyConsumer (абстрактный)
│   ├── Bike
│   │   └── CargoBike
│   └── ElectricBike ------- EnergyConsumer
└── Thing
    ├── Helmet
    └── Dock --------------- EnergyConsumer
```

`ElectricScooter`, `ElectricBike` и `Dock` используют множественное наследование:
от инвентаря через `Transport`/`Thing` и от `EnergyConsumer`.
Здесь нет ромба, поэтому `virtual public` не требуется.

`InventoryItem` содержит чисто виртуальные методы `InventoryId`, `Name`, `Describe`
и виртуальный деструктор. Методы `DailyEnergy` и `ForNovice` вызываются в `Fleet`
через `InventoryItem`, то есть полиморфно, без проверок конкретного типа.

## Перегрузка операторов

В `Inventory.hpp`:
- `operator<<` печатает id и имя через `Describe`;
- `operator<` сравнивает инвентарные номера и используется для сортировки в `list`;
- `operator==` сравнивает id и применяется при проверке на дубликаты.

## Умные указатели

Использовано **последнее уточнение преподавателя** (оно отличается от ранней версии PDF):
- `unique_ptr<InventoryItem>` — временно владеет новым объектом до техосмотра.
  При ошибке кандидат уничтожается и парк не меняется;
- `vector<shared_ptr<InventoryItem>>` — парк хранит принятые объекты;
- `weak_ptr<InventoryItem>` — витрина не владеет объектом. После `remove`
  `show_focus` печатает `removed`, поскольку слабый указатель истёк.

Переход владения сделан в `Fleet::AddItem` после вызова `ServiceCenter::Inspect`.
Сырого `delete` нет.

## Исключения и шаблон

В `Errors.hpp` есть общий `FleetError` (наследуется от `std::runtime_error`),
а от него — `InspectionError` и `InputError`.
Первый бросается при отказе техосмотра. Второй — при неверных аргументах,
неизвестном id/команде, отрицательной энергии, простоте вне 1..10 или повторном id.
Исключения перехватываются в `main`, там же печатается `error: ...`.

`Counter<T>` из `Counter.hpp` — шаблонный класс накопления результата.
Он реально используется как `Counter<double>` для энергии и `Counter<int>`
для количества подходящих новичкам единиц. Без шаблона пришлось бы писать
два одинаковых счётчика под разные типы.

## Что сделал дополнительно

- `CargoBike` — грузовой велосипед: новичку он доступен при простоте
  не меньше установленного порога **и** не меньше 8;
- `count_novice` — отдельный отчёт о числе подходящих новичкам устройств;
- `set_novice` — настройка порога без изменения классов транспорта;
- `report` — число единиц в парке и суммарное потребление.
